# چک‌لیست تست قبل از تحویل (بند ۴۱)

پیش از انتشار، این موارد باید به‌صورت دستی — روی یک پروژه Firebase واقعی —
تست شوند (چون این‌جا امکان اجرای واقعی اپ وجود نداشت):

## ساختار پروژه
- [ ] ۱. ایجاد پروژه جدید از پنل مدیریت
- [ ] ۲. ایجاد چند بلوک با نام‌های متفاوت در یک پروژه
- [ ] ۳. ایجاد طبقات با تعداد متفاوت در بلوک‌های مختلف (مثال بند ۴: بلوک A=۱۹ طبقه، B=۱۵، C=۱۰)
- [ ] ۴. ایجاد تعداد واحد متفاوت در طبقات مختلف همان بلوک (۱۲/۸/۱ طبق مثال)

## چک‌لیست
- [ ] ۵. افزودن فعالیت جدید به یک دسته‌بندی
- [ ] ۶. حذف یک فعالیت (و بررسی حذف زیرمراحل آن)
- [ ] ۷. تعیین وزن روی یک فعالیت اصلی و بررسی اثر آن در پیشرفت وزنی

## کاربران و دسترسی
- [ ] ۸. ایجاد کاربر جدید با Username/Password و ورود موفق با آن
- [ ] ۹. محدودسازی دسترسی کاربر به یک پروژه/دسته‌بندی خاص و تأیید عدم دسترسی به بقیه
      (هم در UI و هم با تلاش مستقیم خواندن سند دیگر پروژه‌ها از طریق Firebase Console → باید Permission Denied بدهد)

## ثبت پیشرفت
- [ ] ۱۰. ثبت یک پیشرفت جدید و بررسی خودکار بودن تاریخ/Username
- [ ] ۱۱. ثبت چند پیشرفت پیاپی برای یک فعالیت/مکان مشخص
- [ ] ۱۲. بررسی این‌که تاریخچه (بند ۱۳) کامل و بدون Overwrite باقی مانده — همه رکوردهای قدیمی در صفحه تاریخچه دیده شوند

## گزارش تاریخی (مهم‌ترین بخش سیستم)
- [ ] ۱۳. تنظیم تاریخ گزارش روی یک تاریخ گذشته و بررسی نمایش صحیح آخرین مقدار <= آن تاریخ
- [ ] ۱۴. تغییر تاریخ گزارش در داشبورد و بررسی به‌روزرسانی همه اعداد/نمودارها/Heatmap

## استقرار نفرات
- [ ] ۱۵. ثبت استقرار روزانه یک پیمانکار
- [ ] ۱۶. مشاهده گزارش استقرار (میانگین/بیشترین/کمترین/تفکیک پیمانکار)

## محاسبات و خروجی
- [ ] ۱۷. بررسی محاسبه پیشرفت وزنی با چند فعالیت وزن‌دار
- [ ] ۱۸. خروجی Excel و بازکردن فایل تولیدشده
- [ ] ۱۹. خروجی PDF و بررسی محتوای گزارش مدیریتی

## امنیت
- [ ] ۲۰. بررسی Firestore Rules: تلاش یک کاربر غیرمجاز برای خواندن/نوشتن روی پروژه/دسته‌بندی خارج از دسترسی‌اش باید رد شود
      (بهترین روش: Firebase Console → Firestore → Rules Playground)

## موبایل
- [ ] ۲۱. اجرای اپ روی حداقل یک دستگاه/شبیه‌ساز Android واقعی و بررسی روانی UI راست‌چین فارسی
